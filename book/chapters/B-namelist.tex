\chapter{The namelist of the case}\label{app:namelist}

This appendix goes through \code{cases/eaton_20250108/namelist.input}, the namelist of the case of \cref{ch:case},
option by option. Where an option has two values, the first is for d01 and the second for d02. The last column says
whether a GPU run may change the option (\emph{varies}) or must keep it (\emph{fixed}). The supported envelope is that
of \code{plan.md} section~2.3: dates and run length, domain sizes, grid spacing, time step, nest position and ratios,
ignition parameters, output intervals and input files may vary; everything else is fixed, and the startup check
\code{gpu_check_config} stops a run that changes it.

\paragraph{Defaults that matter.} Several options of the case are not in the namelist and take their Registry default
values. The port depends on them as much as on the written ones:
\begin{itemize}
  \item \code{rk_ord} = 3, \code{time_step_sound} = 0 (four acoustic steps per time step);
  \item \code{hybrid_opt} = 2, \code{use_theta_m} = 1, \code{hypsometric_opt} = 2;
  \item horizontal and vertical advection of 5th and 3rd order;
  \item \code{fire_viscosity} = 0.4, \code{fire_viscosity_ngp} = 2, \code{fire_lsm_band_ngp} = 4,
    \code{fire_fuel_left_method} = 1, \code{fire_grows_only} = 1, \code{fire_boundary_guard} = 8.
\end{itemize}
The startup check fixes these too.

\paragraph{No \code{namelist.fire}.} The case has no \code{namelist.fire}, so WRF-Fire uses its built-in table of 53
fuel categories (\cref{ch:firebasics}).
