# Work packages of the code-only parallel run (Phases 1–3)

36 work packages cover all coding of Phases 1–3. Rules: [CODE_ONLY.md](CODE_ONLY.md). Interfaces:
[INTERFACES.md](INTERFACES.md). Each work package has a card `wp/<ID>.md` (what it owns, kernel rows with CPU lines,
islands, tasks, notes, "Done") and a status file `wp/status/<ID>.md` that only it writes. The cards, the ownership map
`wp/ownership.json` and the islands `wp/islands/<ID>/` are generated by `port/tools/gen_wp.py` from
`port/tools/wp_def.py`; `check_wp_scope.py <ID>` checks a branch against the ownership.

## How the run is organized

- **Ownership is exclusive.** A routine, a file or a module specification part belongs to exactly one work package.
  Several work packages edit different routines of the same file (e.g. `module_big_step_utilities_em.F` has routines
  of P2-A1, P2-B5, P2-B6, P2-F, P2-G2 and P3-GLUE1). Their changes merge without conflicts because each stays inside
  its own routines.
- **No ordering is needed.** Interfaces are fixed (INTERFACES.md), and every new file exists as a skeleton already
  wired into the build. Every work package can start at once. Where one package calls another's routine (e.g. P1-TAB
  calls the upload routines of P3-WSM6, P3-SFCLAY, P3-NOAH, P3-SW), both write against the interface; the reviewer
  verifies them together.
- **Branches.**
  - Each work package works on `agent/wp/<id>` (its card names it), created from the handoff commit, in its own git
    worktree.
  - The integrator merges finished branches into `agent/code` (`git merge --no-ff`) and pushes.
  - Nobody merges into a work-package branch.
- **Suggested start order**, when fewer than 36 sessions run at once: the hardest and longest first, so they do not
  end up on the critical path at the end.
  1. P3-RRTMG, P2-E1, P2-B1..B4, P3-NOAH, P3-WSM6, P2-G1, P2-G3, P3-PBL, P3-RADDRV, P1-SYNC;
  2. then the rest.

  A worker that finishes takes the next unstarted package.
- **Workers per file.** Two workers may own routines of the same file. Each edits only its own routines, in its own
  worktree.
