# Areas: who works on what

The repository is divided into **areas**:
- each area has one purpose, one entry file with its own instructions, a branch pattern, and the set of paths it may
  change;
- an agent works in **one area at a time**, reads that area's entry file, and changes nothing outside it;
- `port/tools/check_area_scope.py <area>` checks a branch against its area. The reviewer runs it before every merge,
  and a branch that fails it is not merged.

Areas keep agents on dedicated purposes:
- a book agent never sees the port's rules;
- a port worker cannot touch the book;
- two areas never edit the same file, so their branches merge without conflicts.

Inside the port, the code-only run of Phases 1–5 goes further, down to WRF routines: 44 work packages with exclusive
ownership ([port/agent/WORKPACKAGES.md](port/agent/WORKPACKAGES.md)).

## How to start

1. The owner gives you a card or a work package. A card says its area:
   - `python3 roadmap/tools/backlog.py show <ID>` shows the card;
   - `python3 roadmap/tools/backlog.py next --area <area> --env <needs>` lists the open ones.
2. Read the entry file of that area (table below), and only what it and your card name.
3. Work on the area's branch, created from the handoff branch.
4. Before every commit, run both checks; each must print PASS:
   - `python3 port/tools/check_area_scope.py <area> --worktree`, or `... port-wp --wp <ID> --worktree`;
   - `bash port/gates/static.sh`, for the port areas.
5. Push your branch. The reviewer merges it into the handoff branch.

## Branches

| Branch | Content | Who pushes |
|---|---|---|
| `claude/wrf-gpu-port-cpu-7doq8n` | the **handoff branch**: the reviewed state every area starts from | the reviewer only |
| `main` | the same state, updated by the reviewer at milestones; the default branch for visitors | the reviewer only |
| `upstream/v4.6.0` | pristine WRF and WPS 4.6.0 as released by NCAR (never changes) | nobody |
| `agent/code`, `agent/wp/<id>` | the code-only run of Phases 1–3 (integration branch, one branch per work package) | integrator, workers |
| `agent/phase-<N>` | the port on a machine that builds and tests it | the port agent |
| `book/<card>`, `roadmap/<card>`, `perf/<card>`, `docs/<card>`, `ccr/<card>` | one branch per card | that area's agent |

Stage 2 adds `upstream/v4.8.0` and `port/v4.8` (area `versions`); stage 3 adds CFBM (area `cfbm`). Both are closed
until the 4.6.0 port passes G5 (ADR-002 stage gate).
